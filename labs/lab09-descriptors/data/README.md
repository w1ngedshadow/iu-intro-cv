## 0. Что это за занятие и зачем

Студенты извлекут **SIFT**-признаки и покажут числом, почему они инвариантны к масштабу и повороту. Потом
реализуют **Brute-Force Matcher** с **ratio test** Лоу и проверят, что он отфильтровывает неоднозначные
совпадения. В третьей части настроят **FLANN**-матчер для бинарных дескрипторов (ORB) и сравнят скорость с BF.
В четвёртой — применят **геометрическую верификацию** через `cv2.findHomography` + RANSAC, чтобы отсеять
ложные совпадения. Последние 20 минут — клиника ДЗ 2 «Сканер документов» (финальные вопросы).

Три мысли, которые уносят:

**SIFT инвариантен к масштабу и повороту.** Детектор находит экстремумы DoG в пирамиде масштабов; ориентация
назначается по гистограмме градиентов; дескриптор — 128-мерный вектор, приведённый к главной ориентации.
Это золотой стандарт сопоставления, но медленный (слайды 12–16).

**Ratio test фильтрует неоднозначные совпадения.** Если ближайший сосед почти так же близок, как второй,
совпадение отбрасывается. При ratio 0.75 остаётся ~30–50% сырых совпадений; при 1.0 — все, включая ложные.
Но ratio test не проверяет геометрию (слайды 49–51).

**Geometric verification обязательна после matching.** `findHomography` + RANSAC находит модель преобразования
и отбрасывает точки, которые ей не соответствуют. Только инлайеры геометрически согласованы. Минимум 4 точки,
на практике ≥10–15 (слайд 51).

Формат — аудиторная активность: зачёт в классе, 2 %, решение публикуется после пары.

### 4.1. TODO 1 — `bf_match_with_ratio(desc1, desc2, ratio=0.75)` (≈ 12 минут)

Условие. Brute-Force Matcher с ratio test Лоу → список `cv2.DMatch`.

```python
def bf_match_with_ratio(desc1, desc2, ratio=0.75):
    matcher = cv2.BFMatcher(cv2.NORM_L2, crossCheck=False)
    raw_matches = matcher.knnMatch(desc1, desc2, k=2)
    good = []
    for match in raw_matches:
        if len(match) == 2:
            m, n = match
            if m.distance < ratio * n.distance:
                good.append(m)
    return good

При разборе: NORM_L2 для SIFT, NORM_HAMMING для ORB; knnMatch(k=2) — два ближайших соседа;
цикл проверяет len(match) == 2 (на краях может быть меньше); ratio test — m.distance < ratio * n.distance.

Типичные ошибки: неправильная норма; k=1 вместо k=2; нет проверки len(match) == 2; возвращается
raw_matches вместо good.

Вопрос при приёмке: «Почему ratio test, а не просто порог расстояния?» — порог зависит от данных;
отношение d1/d2 нормировано и универсально.

### 4.2. TODO 2 — orb_flann_match(img1, img2, ratio=0.75) (≈ 12 минут)

Условие. ORB + FLANN с ratio test → (kp1, kp2, good_matches).

def orb_flann_match(img1, img2, ratio=0.75):
    orb = cv2.ORB_create(nfeatures=1000)
    kp1, desc1 = orb.detectAndCompute(img1, None)
    kp2, desc2 = orb.detectAndCompute(img2, None)
    index_params = dict(algorithm=cv2.FLANN_INDEX_LSH,
                        table_number=6, key_size=12, multi_probe_level=1)
    search_params = dict(checks=50)
    matcher = cv2.FlannBasedMatcher(index_params, search_params)
    raw_matches = matcher.knnMatch(desc1, desc2, k=2)
    good = []
    for match in raw_matches:
        if len(match) == 2:
            m, n = match
            if m.distance < ratio * n.distance:
                good.append(m)
    return kp1, kp2, good

При разборе: FLANN_INDEX_LSH для бинарных дескрипторов; параметры table_number=6, key_size=12,
multi_probe_level=1 обязательны для LSH; checks=50 — баланс скорости и точности.

Типичные ошибки: FLANN_INDEX_KDTREE для ORB; отсутствуют параметры LSH; checks слишком большой.

Вопрос при приёмке: «Почему FLANN быстрее BF?» — BF — полный перебор O(N·M); FLANN строит индекс и
ищет приближённо за O(log N).    

### 4.3. TODO 3 — verify_matches(kp1, kp2, matches, ransac_thresh=3.0) (≈ 14 минут)

Условие. Геометрическая верификация: findHomography + RANSAC → (H, mask, inlier_matches).

def verify_matches(kp1, kp2, matches, ransac_thresh=3.0):
    if len(matches) < 4:
        return None, None, []
    src_pts = np.float32([kp1[m.queryIdx].pt for m in matches]).reshape(-1, 1, 2)
    dst_pts = np.float32([kp2[m.trainIdx].pt for m in matches]).reshape(-1, 1, 2)
    H, mask = cv2.findHomography(src_pts, dst_pts, cv2.RANSAC, ransac_thresh)
    if mask is None:
        return None, None, []
    mask_bool = mask.ravel().astype(bool)
    inlier_matches = [m for m, ok in zip(matches, mask_bool) if ok]
    return H, mask_bool, inlier_matches

При разборе: координаты извлекаются через kp[m.queryIdx].pt и kp[m.trainIdx].pt; формат (N, 1, 2)
float32 обязателен; cv2.RANSAC — метод robuste estimation; маска преобразуется в bool через
mask.ravel().astype(bool).

Типичные ошибки: координаты не в формате (N, 1, 2); нет проверки len(matches) < 4; маска не
преобразована в bool; ransac_thresh слишком мал.

Вопрос при приёмке: «Зачем RANSAC после ratio test?» — ratio test фильтрует по похожести дескрипторов,
но не по геометрии; на повторяющихся текстурах ложные совпадения проходят ratio test.

### 4.4. TODO 4 — match_pipeline(img1, img2, detector='sift', ratio=0.75, ransac_thresh=3.0) (≈ 10 минут)

def match_pipeline(img1, img2, detector='sift', ratio=0.75, ransac_thresh=3.0):
    if detector == 'sift':
        det = cv2.SIFT_create(nfeatures=500)
        norm_type = cv2.NORM_L2
    elif detector == 'orb':
        det = cv2.ORB_create(nfeatures=1000)
        norm_type = cv2.NORM_HAMMING
    else:
        raise ValueError("unknown detector: %s" % detector)
    kp1, desc1 = det.detectAndCompute(img1, None)
    kp2, desc2 = det.detectAndCompute(img2, None)
    if desc1 is None or desc2 is None or len(kp1) < 4 or len(kp2) < 4:
        return kp1, kp2, [], None
    if detector == 'sift':
        good = bf_match_with_ratio(desc1, desc2, ratio=ratio)
    else:
        _, _, good = orb_flann_match(img1, img2, ratio=ratio)
        kp1_o, desc1_o = det.detectAndCompute(img1, None)
        kp2_o, desc2_o = det.detectAndCompute(img2, None)
        kp1, kp2, desc1, desc2 = kp1_o, kp2_o, desc1_o, desc2_o
    H, mask, inlier_matches = verify_matches(kp1, kp2, good, ransac_thresh)
    return kp1, kp2, inlier_matches, H
